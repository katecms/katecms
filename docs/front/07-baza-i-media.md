# База, медиа и секрет сессии

Это настройки, которые хост задаёт снаружи модуля: объект в `nuxt.config` и переменные процесса.

## База

```ts
interface DatabaseConfig {
  driver?: 'postgres' | 'sqlite'
  url?: string
  sqliteFilename?: string
}
```

Правила выбора движка (их применяет уже адаптер через `resolveDatabaseTarget`):

1. Явный `driver` побеждает.
2. Иначе непустой `url` выбирает Postgres.
3. Иначе SQLite.

Дефолт файла — `data/miraicms.db` относительно `rootDir` приложения. `:memory:` и `file:` URI модуль не переписывает.

Нужен PostgreSQL 15+ (`NULLS NOT DISTINCT` в уникальных индексах). Если `driver: 'postgres'` и `url` пустой, Nuxt-адаптер подставляет `DATABASE_URL`. Ядро само env не читает.

```ts
database: {
  driver: 'postgres',
  url: 'postgres://postgres:admin@127.0.0.1:5432/miraicms',
}
```

При старте Nitro модуль сам применяет схему (один bootstrap, журнал `_miraicms_migrations`) и на Postgres синхронизирует JSONB-индексы полей с `indexed: true`. Повторный старт уже записанные id миграций пропускает. Правка DDL после первого применения в живую базу сама не попадает.

SQLite-файл открывается через `better-sqlite3`, для файла включаются `busy_timeout` и WAL. Каталог родителя создаётся сам.

## Медиа

Каталог всегда `<rootDir>/public/uploads`. Модуль прописывает его в resolved config и не копирует `public/uploads` в серверный бандл (`nitro.ignore`).

| Поле | Дефолт | Смысл |
| --- | --- | --- |
| `maxFileSize` | `10` | Лимит загрузки в мегабайтах. `≤ 0` отбрасывается с warning |
| `allowedMimeTypes` | jpeg, png, webp, gif, pdf, mp4 | Пустой массив запрещает всё. Ключ отсутствует — этот список. `image/svg+xml` в дефолт не входит; если добавить, файл отдаётся как скачивание, а не как страница |
| `maxInputPixels` | `50_000_000` | Бюджет `width × height` для вариантов. Более крупный исходник уменьшается. Заголовок выше 16383×16383 отвергается до декодирования |
| `avif` | `false` | `true` или `{ quality }` от 1 до 100, иначе 80 |
| `webp` | `false` | То же |
| `imageSizes` | `[]` | Пресеты. Имя `full` зарезервировано и игнорируется |

Пресет: `name`, `width?`, `height?` (`0` или пропуск — пропорционально другой стороне), `crop?` (`true` = cover, иначе inside). Увеличения сверх исходника нет.

Варианты строятся для jpeg/png/webp. SVG, PDF и GIF остаются как есть. Матрица: включённые avif/webp полного размера плюс каждый пресет в оригинальном формате и в доп. форматах. Имена вида `photo.webp` и `photo-480x480.webp`.

Поля `image` / `file` / `gallery` могут сузить MIME и размер ещё и у себя. Глобальный список и `maxFileSize` всё равно действуют.

Файлы отдаются по `/uploads/**`. Заголовок ответа зависит от расширения: SVG и HTML-подобные типы не открываются как документ страницы.

## Сессия

Cookie `miraicms_session`, httpOnly, `SameSite=Lax`, `Secure` на https, срок 7 суток. Внутри — id пользователя и `session_version`. Смена пароля увеличивает версию в базе, старая cookie перестаёт подходить. Заблокированный статус `banned` тоже считается выходом.

Секрет подписи:

| Среда | Поведение |
| --- | --- |
| production | `MIRAICMS_SESSION_PASSWORD` длиной от 32 символов. Иначе 500 |
| development | Та же переменная, если она длинная. Иначе встроенный запасной секрет и предупреждение в лог |

Пароль пользователя хранится как scrypt-строка `scrypt$N$r$p$<saltHex>$<hashHex>`. Длина от 8 до 1024 символов. Проверка формата — `validatePassword` / `validateEmail` в ядре. Сообщения об ошибках английские.
